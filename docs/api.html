Space Mission Data API

Read-only, versioned, static JSON — verified data only. ← back to the explorer

Strict mode: every record was compared with, or ingested directly from, a retrieved authoritative source (JPL SSD/SBDB/NHATS, NASA NSSDC, NASA Small Spacecraft SoA report, NTRS, NASA SLS page, Apollo 11 press kit, ULA, ESA, NIST, data.nasa.gov, and the Launch Library 2 aggregator — labelled). Recalled, estimated and fictional values were removed. Records contain only their verified fields; each carries data_class: "verified", source_ids and provenance (field_verification or a collection-level provenance with URL, retrieval date, SHA-256). Keep that visible when you reuse it.

Quick start

Base URL: https://kaungkhantko26.github.io/space-mission-dataset/api/v1. Plain GET of .json files; no keys; CORS open.

curl https://kaungkhantko26.github.io/space-mission-dataset/api/v1/index.json
curl https://kaungkhantko26.github.io/space-mission-dataset/api/v1/planets/mars.json
curl -s https://kaungkhantko26.github.io/space-mission-dataset/api/v1/electric_propulsion.json | jq '.records[] | {id, isp_vac_s, thrust_vac_n}'

Need filtering, NHATS search, Hohmann or Δv? Run the local backend: python3 tools/serve_api.py (see HACKATHON.md).

Collections: planets, moons, asteroids, orbital_elements, atmospheres, moon_mean_elements, rocket_engines, electric_propulsion, launch_vehicles, rocket_stages, boosters, payload_capabilities, missions, launch_vehicle_configs, spacex_launch_history, smallsat_components, smallsat_tables, nasa_missions, nasa_instruments, fluid_properties, nasa_facilities, nhats_targets, neo_catalog, sources. Large collections (nhats_targets, neo_catalog, smallsat_components, launch_vehicle_configs, spacex_launch_history) are served as collection files only. Records from aggregators or vendor compilations carry source_authority and confidence.

Conventions

  • SI units unless the field name says otherwise. NHATS: delta-v in km/s, durations in days, sizes in m. SBDB: a in AU, diameter in km, rotation period in h. JPL moon elements: km, degrees, days.
  • A field that is absent was not verified — it is never zero-filled. verified_fields lists what was checked.
  • Ids are unique within a collection. Foreign keys: vehicle_id, engine_id, parent_id, body_id.
  • Static snapshot regenerated by python3 tools/make_api.py; v1 may gain fields but existing fields will not change meaning.

JavaScript (browser or Node 18+)

<script src="https://kaungkhantko26.github.io/space-mission-dataset/client.js"></script>
<script>
  const api = new SpaceMissionAPI("https://kaungkhantko26.github.io/space-mission-dataset/api/v1");
  const mars = await api.get("planets", "mars");
  const nhats = await api.list("nhats_targets");            // 7,185 real JPL records
  const best = nhats.filter(r => r.min_delta_v_km_s < 6 && r.size_max_m > 100);
</script>

Python (standard library only)

from spacemission_client import SpaceMissionAPI      # tools/spacemission_client.py
api = SpaceMissionAPI()                              # live site; or SpaceMissionAPI("docs/api/v1") offline
thrusters = api.list("electric_propulsion")
print(max(thrusters, key=lambda e: e["isp_vac_s"])["name"])
print(api.ideal_delta_v(thrusters[0], m0=1000, mf=400))

With pandas: pd.DataFrame(api.list("neo_catalog")), or read exports/csv/*.csv.

Reuse rules

  1. Show data_class/provenance in your UI; do not present results as official NASA/JPL/ESA/ULA output.
  2. Do not fill missing fields with guesses — treat absence as "unknown".
  3. Licences: see LICENSE-DATA.md (NASA/JPL public data; the NASA Facilities table lists its licence as "not specified").
