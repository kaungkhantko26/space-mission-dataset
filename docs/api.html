Space Mission Data API

Read-only, versioned, static JSON. Everything in the Explorer is available here. ← back to the explorer

Data status: external figures are unverified (no source was retrieved), derived values inherit that, optimizer catalog values are estimated, credits are fictional, and the SpaceX/NASA-facility tables are user-supplied files whose origin and license are unverified. Every record carries data_class, confidence and source_ids — please keep them when you reuse data.

Quick start

Base URL: https://kaungkhantko26.github.io/space-mission-dataset/api/v1. Every endpoint is a plain GET of a .json file. No keys, no rate limit beyond GitHub Pages' own, and CORS is open (Access-Control-Allow-Origin: *), so browsers can call it directly.

curl https://kaungkhantko26.github.io/space-mission-dataset/api/v1/index.json
curl https://kaungkhantko26.github.io/space-mission-dataset/api/v1/launch_vehicles/falcon_heavy.json
curl -s https://kaungkhantko26.github.io/space-mission-dataset/api/v1/rocket_engines.json | jq '.records[] | {id, isp_vac_s, thrust_vac_n}'

Conventions

  • SI units; unit is in the field name (_kg, _n, _w, _m_s, _km3_s2…). null means not recorded — never zero.
  • Ids are lowercase snake_case and unique within a collection. Foreign keys: engine_id, vehicle_id, launch_vehicle_id, instrument_ids, parent_id, body_id, launch_site_id, source_ids, scenario_id.
  • Responses may gain new fields in v1; existing fields will not change meaning. Breaking changes ship as v2.
  • The API is regenerated by python3 tools/make_api.py after every build; it is a snapshot, not a live service. Optimization is not exposed as an endpoint — use the client libraries below (they run the same model in your process).

JavaScript (browser or Node 18+)

<script src="https://kaungkhantko26.github.io/space-mission-dataset/client.js"></script>
<script>
  const api = new SpaceMissionAPI("https://kaungkhantko26.github.io/space-mission-dataset/api/v1");
  const mars = await api.get("planets", "mars");
  const stage = await api.expand(await api.get("rocket_stages", "f9_s1"));   // follows engine_id / vehicle_id / source_ids
  console.log(stage._linked.engine_id.record.name, stage._linked.vehicle_id.record.name);
  const hits = await api.search("falcon");
  const front = await api.pareto("lunar_orbiter");
</script>

Re-running the optimizer yourself: load model.js (enumerate, solve, balanced, pareto) and pass it (await api.scenarios()) — see tools/parity_check.js for a complete example.

Python (standard library only)

from spacemission_client import SpaceMissionAPI      # tools/spacemission_client.py
api = SpaceMissionAPI()                              # live site
# api = SpaceMissionAPI("docs/api/v1")               # offline, from a local checkout
engines = api.list("rocket_engines")
best = max((e for e in engines if e["isp_vac_s"]), key=lambda e: e["isp_vac_s"])
print(best["name"], best["isp_vac_s"], best["data_class"])
print(api.ideal_delta_v(best, m0=1000, mf=400))      # Tsiolkovsky; None if Isp not recorded

With pandas: pd.DataFrame(api.list("nasa_facilities")).

Using it from another project (e.g. a simulator)

  1. Fetch index.json once and cache; it lists collections and counts.
  2. Load the records you need and filter by data_class — treat anything not verified as teaching data.
  3. Show data_status or the record's data_class in your UI; do not present it as official NASA/SpaceX specifications.
  4. Pin to api/v1. If you need a frozen copy, download the files from the repository's docs/api/v1 folder or the combined file docs/data/all_space_mission_data.json.

Licensing: no license file is set yet; the uploaded SpaceX and NASA-facility files have unverified licenses, so check before redistributing those collections.
